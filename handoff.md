## 2. Реестр скиллов проекта (ОБЯЗАТЕЛЬНО К ИСПОЛЬЗОВАНИЮ В НОВЫХ ОКНАХ)

При открытии новой сессии агент **ОБЯЗАН** ориентироваться на следующий профиль скиллов:

### Основной стек скиллов (Core Engine & Architecture)
1. **`siemens-tia-portal`** — доменная инженерная логика:
   - Спецификации Siemens TIA Portal V14–V20.
   - WinCC Unified: SQLite WAL, сегменты кратно 4 МБ, кольцевой буфер $\ge 3$ сегментов, минимальный размер архива 200 МБ.
   - WinCC Comfort/Advanced: RDB/CSV, лимит 500 000 записей на файл, аппаратный лимит 32 ГБ (FAT32).
   - WinCC Professional: Fast Tag Logging ($\le 1$ с) и Slow Tag Logging ($> 1$ с), лимит 10 ГБ SQL Express.
2. **`isa-18-alarm-rationalization`** — стандарты сигнализации:
   - Расчет частоты алармов по ISA-18.2 и EEMUA 191 (пороги: 6, 12, 30 алармов/час).
   - Детектирование риска лавины тревог (Alarm Flood).
   - **Важное правило**: отображать *исключительно как инженерную рекомендацию (Advisory)*, не блокировать расчеты.
3. **`ponytail`** — философия минимализма и простоты (YAGNI):
   - «Delete before add. Boring over clever».
   - Никаких тяжелых стейт-менеджеров (Redux, Zustand) — только нативные React хуки.
   - Никаких раздутых внешних библиотек для генерации PDF/DOCX (используется нативная печать браузера `window.print()`).
4. **`xlsx`** — работа с таблицами Excel:
   - Экспорт рабочих книг `.xlsx` по строгой структуре TIA Portal (`Hmi Tags`, 30 столбцов, `Substitute Value Usage`).
   - Парсинг файлов импорта через безопасный стек.
5. **`code_cleaner`** — чистота кода и React 19:
   - 0 предупреждений ESLint.
   - **Жесткое правило React 19**: категорический запрет на вызов `setState` внутри `useEffect`. Все зависимые состояния вычисляются на лету (derived state) или лениво (`useState(() => ...)`).
6. **`security_audit`** — безопасность:
   - Проверка зависимостей (`npm audit`).
   - Защита от утечек токенов (токены только через скрипты, маскировка `[REDACTED]`).
7. **`commit_helper`** — культура версионирования:
   - Conventional Commits (`feat:`, `fix:`, `docs:`).
   - Строгая фиксация автора коммитов.
8. **`readme-docs-generator`** — поддержание актуальности документации `README.md` при любых изменениях.
9. **`ui-ux-pro-max` / `frontend-design`** — индустриальный интерфейс:
   - Адаптивность для мобильных устройств (2-рядная шапка, переносимый тулбар тегов).
   - Темная тема и фирменная палитра Siemens (Petrol `#00646E` / Dark Slate).
10. **`i-have-adhd`** — стиль общения с пользователем:
    - Конкретные действия сразу на первой строке.
    - Нумерованные короткие списки, отсутствие вводных фраз и «воды».

### Отсекаемые скиллы (ЗАПРЕЩЕНО использовать в этом проекте)

## 3. Политика версионирования (SemVer)
Версии обновляются синхронно в `package.json` и в шапке `src/components/Header.tsx`:
* **MAJOR (X.0.0):** Только фундаментальные архитектурные переработки фреймворка или модели данных.
* **MINOR (0.X.0):** Добавление совершенно новой панели или функциональной подсистемы (например, новый тип HMI).
* **PATCH (0.0.X):** Любые доработки в рамках существующих панелей: исправление багов, валидации, рекомендации (включая ISA-18.2), тексты, UI-полировка, обновление документации.

  - `tiaExporter.ts` — генерация `.xlsx` и `.csv` для TIA Portal.

* **Компоненты интерфейса (`src/components/`)**:
  - `tabs/UnifiedTab.tsx`, `tabs/ComfortTab.tsx`, `tabs/ProfessionalTab.tsx` — вкладки систем.

  - `ReportModal.tsx` — печатный отчет проекта (SIOS BoM + расчет).
  - `TiaCheatSheetModal.tsx` — шпаргалка TIA Portal и SIOS чек-лист монтажа накопителей.
  - `IndustryPresetsModal.tsx` — отраслевые шаблоны (КНС, Котельная, GMP, HVAC).
